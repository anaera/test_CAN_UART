# giga_ram.X — тестовый стенд CAN-подобной шины на UART (PIC16F1825)

Проект для отладки низкоуровневого драйвера **UART_driver** и прикладного слоя **UCAN_driver** на микроконтроллере **Microchip PIC16F1825** с компилятором **MPLAB XC8 v4.0**.

Шина эмулирует поведение CAN-подобного протокола: **один логический бит = один UART-байт**, битовый арбитраж, CRC, межкадровый интервал GAP, multi-master доступ.

## Назначение

Проект — **лабораторный стенд**, а не готовый CAN-стек:

- проверка машины состояний приёма/передачи на общей UART-линии;
- отладка арбитража, GAP-таймаута, CRC;
- наблюдение фаз на GPIO (логический анализатор);
- минимальный прикладной слой (`UCAN_driver`) для формирования/разбора пакетов.

## Архитектура ПО

### UART_driver (низкий уровень)

- Кодирует логические биты в UART-байты.
- Ведёт машину состояний: `IDLE`, `RECV`, `SEND`, `SKIP`.
- Обрабатывает арбитраж (первые 12 бит кадра).
- Считает CRC побитово при приёме; побайтово при передаче (`updByteCRC`).
- Управляет GAP через **TMR0** (~200 µs при `SPEED_NUM=2`).

### UCAN_driver (прикладной уровень)

- Формирует пакет `packCAN_t` (заголовок + data + CRC).
- Периодически (раз в 100 ms) ставит пакет на передачу.
- При приёме — минимальная обработка тестового байта (`tmpUART`).

Фильтрация по `node` / `cmd` / `len` — **следующий слой** (см. [Примечания](#примечания)).

---

## Протокол и кодирование

| Логический бит | UART-байт | Комментарий |
|----------------|-----------|-------------|
| 0 (dominant) | `0x00` | доминирует на шине |
| 1 (recessive) | `0xFC` | |
| Выборка | маска `0x10` | бит 4 принятого байта |

- UART: **LSB first**, 8N1.
- Скорость: таблица `tab_load_SPBRGL[]`, по умолчанию `SPEED_NUM=2` (~125 kbit/s UART, ~8 µs на UART-бит).
- **Доминантный 0**: при коллизии «0 vs 1» или «0 vs 0» в точке выборки всегда читается **0** — основа арбитража.
- CRC: полином `0x31`, проверка — остаток `crcByte == 0` после приёма всего кадра.

## Машина состояний драйвера

| Состояние | Значение | Описание |
|-----------|----------|----------|
| `IDLE_STEP` | 0x00 | Ожидание активности шины или постановки TX |
| `RECV_STEP` | 0x01 | Приём кадра |
| `SEND_STEP` | 0x02 | Передача кадра |
| `SKIP_STEP` | 0x03 | Ошибка: доприём до GAP, затем IDLE |

### Переходы

```
                    INT (start bit)
         IDLE ─────────────────────► RECV
          │                            │
          │ sndIsFull                  │ успех / ошибка
          ▼                            ▼
         SEND ──арбитраж проигран──► RECV
          │                            │
          └──── ошибка ──► SKIP ◄──────┘
                              │
                         GAP (TMR0)
                              ▼
                            IDLE
```

### GAP (межкадровый интервал)

После **любого** завершения кадра (успех, SKIP, ошибка) узел остаётся в активном состоянии до истечения **GAP** на TMR0, затем переходит в `IDLE`. Это сделано **намеренно**, чтобы все узлы синхронно выходили в IDLE и не захватывали шину раньше остальных.

Макрос:

```c
#define SET_GAP() { TMR0 = constUART.loadTMR0; INTCONbits.TMR0IF = 0; }
```

Сброс `TMR0IF` при каждом `SET_GAP()` предотвращает гонку «INT + уже висящий TMR0IF» в одном ISR.

## API

### UART_driver.h

| Функция | Назначение |
|---------|------------|
| `initDriverUART()` | Инициализация UART, TMR0, INT, констант |
| `sendPack(uint8_t *ptr)` | Поставить буфер на передачу (`TX_RETRY` попыток) |
| `checkSendPack(uint8_t *ptr)` | Безопасная постановка (TX свободен, RX не занят) |
| `recvPack()` | Указатель на буфер принятого кадра `rxUART[11]` |
| `isRxReady()` / `clrRxReady()` | Флаг «кадр принят» |
| `isTxReady()` | TX-буфер свободен |
| `getError()` / `clrError()` | Маска ошибок / сброс |
| `setEcho()` / `clrEcho()` | Эхо-режим после успешной TX |
| `updByteCRC(crc, byte)` | CRC одного байта (для TX) |

ISR вызывает: `engineUART()`, `setStateReceive()`, `nextStepIDLE()`.

### UCAN_driver.h

| Функция | Назначение |
|---------|------------|
| `initDriverUCAN()` | `node_owner = 0x0A` |
| `sendPackUCAN()` | Сформировать и отправить тестовый пакет |
| `recvPackUCAN()` | Забрать принятый пакет (тестовая логика) |
| `packSendSelect()` | Выбор данных для TX (cmd=0x07, len=1) |

## Формат пакета UCAN

Структура `packCAN_t` (11 байт):

```
┌─────────────────────────────────────────────────────────┐
│ hiHead │ loHead │ data[0..7] │ crc                       │
│ node/cmd │ len/rtr/node │                              │
└─────────────────────────────────────────────────────────┘
```

Поля заголовка (16 bit):

- `hiNode` (4), `cmd_can` (4)
- `lenData` (4), `rtr` (1), `loNode` (3)

Максимум **8** байт данных (`MAX_LEN_DATA`). CRC считается по заголовку + data и записывается после data.

## Таймеры и прерывания

| Таймер | Период | Назначение |
|--------|--------|------------|
| **TMR0** | ~200 µs | GAP, выход в IDLE |
| **TMR2** | 1 ms | `hardSystem` (системный тик) |
| **TMR1** | 100 ms | `hardTime` → вызов `sendPackUCAN()` |

### ISR (`isr.c`) — порядок обработки

1. **RCIF** → `engineUART()` (приём/передача бита)
2. **INT / IOC** → `setStateReceive()` (start активности шины)
3. **TMR0IF** → `nextStepIDLE()`
4. **TMR2IF** → `setSystemTick()`
5. **TMR1IF** → `setTimeTick()`

Порядок **RCIF/INT перед TMR0** важен для корректной работы GAP.

| Пин | Сигнал | Назначение |
|-----|--------|------------|
| RA0 | RECV | Низкий уровень в `RECV_STEP` |
| RA1 | SEND | Низкий уровень в `SEND_STEP` |
| RC0 | SKIP | Toggle в `SKIP_STEP` при приёме байта |
| RC1 | INT | Toggle при входе в приём по INT |

## Тестовый сценарий (main)

1. `initChip()` → `initDriverUCAN()` → `initDriverUART()`
2. Настройка отладочных GPIO
3. `systemStart()` — включение прерываний
4. Бесконечный цикл:
   - постоянно `recvPackUCAN()`
   - каждые **100 ms** — `sendPackUCAN()`

Тестовый пакет: `cmd=0x07`, `lenData=1`, `data[0]=tmpUART`, `tmpUART` инкрементируется при каждой отправке; при приёме `tmpUART = raw[2] + 1`.

Для двухузлового теста: два PIC с разными `node_owner`, общая UART-линия, общий INT/start.

## Коды ошибок

| Маска | Имя | Описание |
|-------|-----|----------|
| 0x01 | `eUART` | Overrun UART (OERR) |
| 0x02 | `eSEND` | Ошибка передачи бита (вне арбитража) |
| 0x04 | `eLEN` | Недопустимая длина data (>8) |
| 0x08 | `eCRC` | Ошибка CRC |
| 0x10 | `eRxD` | Переполнение RX (пакет не забран) |
| 0x20 | `eTxD` | Исчерпаны повторы TX |
| 0x40 | `ePDO` | (зарезервировано) |
| 0x80 | `eARBIT` | Проигран арбитраж (диагностика) |

Ошибки накапливаются (`OR`) до вызова `clrError()`.

## Примечания

Раздел фиксирует проектные решения и уточнения из ревью кода.

### 1. Гонка INT + TMR0IF

**Проблема:** в одном ISR сначала обрабатывался INT (вход в RECV), затем уже установленный `TMR0IF` вызывал `nextStepIDLE()` и сбрасывал приём.

**Решение:** макрос `SET_GAP()` перезагружает TMR0 **и сбрасывает `TMR0IF`**. Все входы в активную фазу и продления GAP идут через `SET_GAP()`. Порядок в ISR: RCIF/INT **до** TMR0.

### 2. GAP до IDLE (CLR_GAP не используется)

После успешного кадра узел **не** выходит в IDLE сразу — ждёт полный GAP, как после SKIP. Это **намеренно**: все узлы одновременно переходят в IDLE и получают равные условия доступа к шине. Ускорение через `CLR_GAP()` имело бы смысл только на одноузловом стенде без требования синхронного Idle.

### 3. eARBIT — диагностика, не авария

`eARBIT` (0x80) выставляется при штатном проигрыше арбитража для анализа поведения шины. Не следует трактовать его наравне с `eCRC` / `eSEND` как «битый кадр», когда верхний слой начнёт принимать решения по `getError()`.

### 4. FERR намеренно не обрабатывается

Проверяется только **OERR** (переполнение FIFO).

При кодировании `0→0x00`, `1→0xFC`, выборка `0x10`, доминантный **0** на stop-бите даёт **FERR**, но в точке выборки маска всё равно даёт логический **0** — корректный исход арбитража/коллизии. UART после чтения `RCREG` продолжает работу. Перевод в SKIP по FERR **не требуется** для данной физики шины.

### 5. Retry при арбитраже

- При каждой попытке SEND: `cntRetrySend--`.
- При проигрыше арбитража (dominant 0 при нашей 1 в зоне первых 12 бит): `cntRetrySend++` — попытка **не засчитывается**.
- При реальной ошибке (eSEND, OERR, CRC…) — increment **нет**, попытка потрачена.
- Бюджет: `TX_RETRY=3`; при `cntRetrySend==0` — `eTxD`.
- Поле `cntRetrySend` — 3 бита (0…7). При текущем `TX_RETRY=3` wrap недостижим. Если `TX_RETRY` вырастет до 7, имеет смысл насыщение: `if (cntRetrySend < TX_RETRY) cntRetrySend++`.

### 6. CRC побитово

Побитовый CRC в `engineUART` использует `(stateUART.rcvBit << 7)` — эквивалент XOR с MSB CRC до сдвига. Побайтовый `updByteCRC()` на TX менять не нужно. Зависимость от layout bitfield в union для CRC снята явной формой.

### 7. node / cmd / len

Проверка адресации и типа команд — **не задача UART_driver** и текущего тестового `UCAN_driver`. Планируется в следующем прикладном слое над `recvPackUCAN()`.

### 8. Common RAM и `#pragma udata access`

`#pragma udata access` — наследие MPLAB C18; **XC8 v4** для PIC16 не размещает переменные в Common так, как ожидалось. Для доступа без `BANKSEL` — явное размещение:

```c
volatile uCAN_state_t stateUART __at(0x70);
```

с контролем `.map` на пересечение со scratch/stack компилятора (0x70–0x7F).

### 9. Разделение UART_core.h / UART_driver.h

- `UART_core.h` — состояния, типы, внутренние inline/static объявления.
- `UART_driver.h` — публичный API для приложения и ISR.

`INT_RA2` сейчас определён в обоих заголовках — при смене конфигурации INT держать определение в **одном** месте.

### 10. Изменение числовых кодов состояний

Актуальные значения: `IDLE=0`, `RECV=1`, `SEND=2`, `SKIP=3`. При документировании осциллограмм не путать со старыми значениями (0x03/0x04/0x05).
